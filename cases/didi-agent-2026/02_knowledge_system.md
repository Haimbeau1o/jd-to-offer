# 配套知识体系

## 学习顺序

1. 先补通用基础：Python / PyTorch / Transformer / 服务化
2. 再补岗位核心：Agent、后训练、奖励设计、评测
3. 最后补业务映射：网约车供需、司机经营、策略指标

## 强化学习与奖励设计

- 优先级得分：29
- 命中关键词：奖励函数、ppo、grpo、dpo、rlvr、强化学习、数据反馈、优化机制
- 必学子主题：
  - PPO、DPO、GRPO 的目标函数与适用边界
  - 可验证奖励、规则奖励、模型奖励的组合方式
  - reward hacking、长度偏差与离线评测
  - 基于日志失败样本的数据回灌闭环
- 项目要体现：
  - 需要展示 reward 设计与失败案例
  - 需要展示偏好数据或可验证奖励数据构造
- 面试要会讲：
  - 如何防止 reward hacking？
  - DPO 和 PPO 的主要差异是什么？

## Agent 系统设计

- 优先级得分：27
- 命中关键词：agent、意图识别、复杂任务拆解、多步推理、react、工具调用、长短期记忆、智能推荐、function call
- 必学子主题：
  - Agent 基础范式：router / planner / actor / memory / evaluator
  - ReAct 与 function calling 的适用边界
  - 工具 schema 设计、参数填充与异常恢复
  - 任务完成率、工具调用正确率、步骤冗余率等评测指标
- 项目要体现：
  - 需要有端到端 Agent 主链路
  - 需要展示工具调用与记忆模块
- 面试要会讲：
  - 为什么这里需要 Agent，而不是纯 RAG？
  - 如何避免 Agent 死循环或错误工具调用？

## 后训练与对齐

- 优先级得分：25
- 命中关键词：sft、rl、后训练、上下文遵循、领域问答、rlhf、cpt、pre-train
- 必学子主题：
  - Pre-train / CPT / SFT / Preference Optimization / RL 的关系
  - 指令数据构造与多轮样本设计
  - 上下文遵循与格式遵循的可量化定义
  - 训练前后离线评测方法
- 项目要体现：
  - 需要展示训练数据设计
  - 需要展示 SFT 或偏好优化实验
- 面试要会讲：
  - 为什么先做 SFT 再做 RL？
  - 如何定义并优化上下文遵循？

## 前沿推理方法

- 优先级得分：15
- 命中关键词：多智能体、long context、cot、多步推理、国际前沿技术
- 必学子主题：
  - CoT、ReAct、Multi-Agent、Long Context 的收益与边界
  - 推理质量与时延/成本之间的 trade-off
  - 长上下文污染与检索替代方案
- 项目要体现：
  - 需要能解释为什么不用过度复杂的多智能体设计
  - 需要体现方法选型依据
- 面试要会讲：
  - 多智能体什么时候有价值，什么时候是过度设计？
  - Long Context 与检索增强各自解决什么问题？

## 网约车供需策略理解

- 优先级得分：14
- 命中关键词：网约车业务、司机智能助手、供需策略、司机、业务迭代
- 必学子主题：
  - 司机经营问题、活动推荐、热区建议、规则答疑等典型场景
  - 供需平衡、司机活跃、订单响应率等业务指标
  - 模型能力如何映射为平台效率与司机体验改进
- 项目要体现：
  - 需要项目场景贴近司机经营与供需问题
  - 需要解释业务指标与模型指标关系
- 面试要会讲：
  - 司机侧 Agent 的核心价值指标有哪些？
  - 供需策略场景下，为什么需要可解释推荐？

## 训练与推理基础设施

- 优先级得分：14
- 命中关键词：pytorch、megatron-lm、deepspeed、vllm、sglang、推理框架、训练全流程
- 必学子主题：
  - PyTorch autograd、AMP、分布式训练基础
  - ZeRO、TP、PP、DP 等并行概念
  - vLLM / SGLang 的吞吐、时延、KV cache 与批处理机制
  - 训练与服务接口的一致性问题
- 项目要体现：
  - 需要展示训练与推理承载层选型理由
  - 需要展示服务接口或离线推理脚本
- 面试要会讲：
  - 为什么选 vLLM 或 SGLang？
  - 训练框架和推理框架的职责边界是什么？

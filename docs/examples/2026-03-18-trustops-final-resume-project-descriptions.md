# TrustOps 双项目终版简历描述

## 使用原则

- 投电商安全 / 风控后端 / 商家治理后端：主写 `trustops-ecommerce-riskops-platform`
- 投内容质量 / AI 工具开发 / 数据服务平台：主写 `trustops-content-quality-platform`
- 简历只能放 1 段项目：使用“合并版”

这份文档只保留可直接复制进简历的终版表述，避免写成过长项目介绍。

## 版本 A：投电商安全 JD

### 项目名称

`TrustOps Ecommerce RiskOps Platform｜电商安全后端平台项目`

### 一句话介绍

面向电商安全与商家风险运营场景，设计并实现风险事件接入、案件流转、审计查询与异步治理主链路，重点体现后端平台抽象、稳定性治理与 B 侧运营支撑能力。

### 4 条终版 Bullet

- 设计并实现电商安全后端平台，基于 `Go + Hertz + MySQL + Redis + RabbitMQ` 搭建风险事件接入、案件生成、审计查询与异步消费主链路。
- 围绕风险治理场景抽象 `Event / Case / Audit / Outbox` 领域模型，支撑商家风险运营与案件协同处理，强化业务逻辑拆分与服务化实现能力。
- 实现请求幂等、事务 outbox、消费者持久化去重、API Key 鉴权与限流，提升异步链路一致性、系统安全性与运行稳定性。
- 补齐审计日志查询、Prometheus 风格指标与 AI Copilot sidecar 风险摘要能力，在不影响主判定链路的前提下增强运营排查效率与系统可观测性。

### 2 条精简补充 Bullet

- 基于 MySQL、Redis、RabbitMQ 组合实现可靠异步处理与查询加速，覆盖失败重试、死信治理与重复消费控制。
- 将 AI 能力限制在 sidecar 增强链路，只提供摘要和排查建议，体现对高可靠、高安全后端系统边界的理解。

## 版本 B：投内容质量 / AI 工具开发 JD

### 项目名称

`TrustOps Content Quality Platform｜内容质量与数据服务平台项目`

### 一句话介绍

面向内容质量治理与数据服务场景，设计并实现事件接入、案例流转、审计追踪、异步处理与 AI sidecar 增强链路，重点体现工具线上化、数据服务与后端工程能力。

### 4 条终版 Bullet

- 设计并实现内容质量与数据服务平台，基于 `Go + Hertz + MySQL + Redis + RabbitMQ` 搭建事件接入、案例流转、审计查询和异步消费主链路。
- 将鉴权、限流、幂等、事务 outbox、消费者持久化去重与指标导出作为平台基础能力前置，强化高可靠、高安全、可观测的后端服务设计。
- 以 `Python + FastAPI` 形式集成 AI Copilot sidecar，支持案例摘要、规则解释与辅助分析，体现大模型工程化接入与失败回退边界设计。
- 对外提供案例查询、审计查询和指标接口，体现“工具线上化 + 数据服务 + 平台复用模块”的完整后端工程实现。

### 2 条精简补充 Bullet

- 基于事件、证据、案例、审计等核心对象进行模块化建模，提升复杂业务流程的抽象和拆分能力。
- 保持 AI 增强链路与主判定链路解耦，确保系统可控、可审计、可回退。

## 版本 C：通用后端平台合并版

### 项目名称

`TrustOps Platform｜面向电商安全与内容质量场景的后端平台样板`

### 一句话介绍

抽象并实现可复用的 TrustOps 后端平台骨架，在电商安全和内容质量两个业务域验证事件接入、案例流转、审计查询、异步治理、可观测性与 AI sidecar 增强能力的复用性。

### 4 条终版 Bullet

- 设计并实现可复用的 TrustOps 后端平台，统一抽象 `Event / Case / Audit / Outbox / Worker` 核心模型，并分别落地到电商安全与内容质量两个业务域。
- 基于 `Go + Hertz + MySQL + Redis + RabbitMQ` 完成事件接入、案例查询、审计追踪、异步消费与运营数据接口，体现扎实的后端服务工程能力。
- 通过请求幂等、事务 outbox、消费者持久化去重、API 鉴权、限流和 `/metrics` 指标导出，补齐线上后端服务常见的稳定性与安全治理能力。
- 使用 `Python + FastAPI` 以 sidecar 方式接入 AI Copilot，提供摘要、解释和辅助分析能力，同时保证 AI 不进入主判定链路。

## 简历篇幅不足时的 3 条短版

- 基于 `Go + MySQL + Redis + RabbitMQ` 实现幂等、事务 outbox、消费者去重、鉴权、限流与指标观测，强化服务稳定性与安全性。
- 以 `Python + FastAPI` 集成 AI sidecar 增强模块，提供摘要和解释能力，并保持主判定链路可控、可审计。

## 技能点映射写法

### 电商安全 JD 优先强调

- 后端开发
- 业务抽象与服务化拆分
- 电商安全 / 风险治理 / B 侧运营支撑
- 数据结构、异步链路、一致性治理
- 鉴权、限流、审计、可观测性

### 内容质量 / AI 工具 JD 优先强调

- 工具线上化
- 数据服务接口
- Go / Python 双语言后端工程
- MySQL / Redis / RabbitMQ
- AI 工程化接入与边界控制

## 不要这样写

- 不要写“提升风控召回率”“降低误杀率”“支撑千万级流量”等无法自证的数据结果。
- 不要把项目写成“AI 决策系统”，这会削弱后端主链路和工程边界。
- 不要把两个项目写成换壳重复项目，核心表述必须是“同一平台抽象在不同业务域的复用验证”。

## 最推荐的简历摆放方式

- 主项目：`TrustOps Ecommerce RiskOps Platform`
- 补充项目：`TrustOps Content Quality Platform`
- 补充项目只保留 1 到 2 条，证明平台复用能力即可

### 投内容质量 / AI 工具 JD

- 主项目：`TrustOps Content Quality Platform`
- 补充项目：`TrustOps Ecommerce RiskOps Platform`
- 补充项目强调“同类平台能力迁移到另一业务域”
